# ОКО ТПУ — как команда работает с Claude

Главный принцип: **репозиторий — общая память команды.** Всё, что Claude должен знать, лежит в git: `contracts/`, `docs/`, `CLAUDE.md` и файлы по папкам. Договорились в чате или на созвоне — это не существует, пока не попало в репозиторий.

У каждого участника свой аккаунт Claude. Общих чатов и общей памяти между ними нет. Поэтому одинаковое поведение задаёт `CLAUDE.md`, а не чья-то переписка.

## 3. Как ставить задачу

Одна задача — один пункт из ТЗ или одна операция из спецификации. Шаблон:

```
Задача: <пункт ТЗ или operationId из спецификации>, например createKey.
Контекст: contracts/oko-openapi.yaml — операция createKey и схема ApiKeyIssued;
          docs/db.md — таблица api_key; backend/CLAUDE.md — раздел «Ключи».
Что сделать: <эндпоинт, сервис, миграция>.
Готово, когда: тесты на успех и ошибки из спецификации; ответ проходит схему;
               сборка и тесты backend/ зелёные.
Ограничения: contracts/ не меняем. Сначала план, код — после моего ок.
```

Полезные приёмы:

| Приём | Когда |
|---|---|
| Режим планирования | задача затрагивает больше одного файла |
| `/clear` | между задачами, иначе старый контекст мешает |
| «Сначала тест, потом код» | приём оценок, права, агрегаты, окна до/после |
| «Прочитай раздел X файла Y» | спецификация большая, не читать целиком без нужды |
| «Сверь мой дифф со спецификацией» | перед каждым PR |

## 4. Git и ревью

- `main` — только то, что прошло приёмку. Работа идёт в `dev`. В `dev` — только через PR, CI зелёный.
- Ветка на задачу: `feat/create-key`, `fix/last-owner-race`.
- PR — до ~400 строк. В описании: какой пункт ТЗ закрывает и как проверить.
- Ревьюер — другой разработчик. Данил и Таир смотрят PR друг друга в своих зонах.
- Изменения в `contracts/` — аппрув аналитика и той стороны, которой это касается.
- **Автор коммита — человек.** Claude указывается строкой `Co-Authored-By` в конце сообщения.
- Код от Claude коммитит тот, кто его прочитал и понимает. «Claude так сгенерировал» — не объяснение ни на ревью, ни на защите.

## 5. Безопасность

- Ключи, `client_secret`, HMAC-секрет, пароли — только в `.env` (в `.gitignore`) и в секретах CI. В чат с Claude не вставляем.
- `.env` и `secrets/` закрыты для чтения в `.claude/settings.json`. Если нужен пример конфига, есть `.env.example` без значений.
- Выгрузки с персональными данными (ФИО, email, идентификаторы ТПУ) в репозиторий и в чат не попадают. Для примеров — выдуманные данные.
- Опасные команды (`push --force`, `reset --hard`, удаление томов Docker) Claude не выполняет без подтверждения.
- Если Claude сгенерировал код, который работает с ключами или сессиями, его проверяет человек, а не только тесты.
