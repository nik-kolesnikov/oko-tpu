# Frontend и виджет ОКО

Зона: Таир. Контракт: `../contracts/oko-openapi.yaml`. Макеты: Figma, владелец — Максим.

Экраны здесь не описываем. Реализуем по макету. Если макет и спецификация расходятся, спрашиваем Максима или Николая, а не придумываем.

## Структура

```
frontend/
├── src/           панель (React SPA): вход, дерево продуктов, карточка продукта, форма продукта, админ
├── widget/        виджет для чужих сайтов: loader.js и frame.js; не React
└── mock/          мок-сервер по спецификации — фронт работает на нём до готовности backend (есть и режим Prism)
```

## Панель

- Работаем только на данных API. Не обращаемся к полям, которых нет в спецификации.
- У каждого экрана три состояния: загрузка, пусто, ошибка.
- Тексты оценок, названия и комментарии выводятся как текст, не как HTML. `dangerouslySetInnerHTML` и `innerHTML` не используем.
- Изменяющие запросы отправляем с `X-XSRF-TOKEN` из cookie `XSRF-TOKEN`.
- Ключи при создании продукта не выпускаем. На вкладке «Интеграция» без публичного ключа — пустое состояние с кнопкой «Выпустить публичный ключ».
- Полный ключ, и публичный, и секретный, приходит только в ответе на выпуск или перевыпуск. Показываем его сразу, затем очищаем состояние и не сохраняем нигде. Потом виден только префикс.
- Потерянный ключ не восстанавливается: перевыпуск и замена кода вставки на всех сайтах. Так и пишем во вкладке «Интеграция».
- Ключи и токены не кладём в `localStorage` и `sessionStorage`.
- Лампочки — по статусам из API. Цвет и подпись: `up` — зелёный, `degraded` — жёлтый «частично не работает» (только у продукта), `down` — красный, `unknown` — серый «нет данных».
- Лампочку продукта на карточке считаем из сервисов по правилу `ProductHealthStatus` из контракта (`src/lib/health.ts`). Дашборд отдаёт её готовой.

## Виджет — зона повышенного риска

Виджет работает на чужих сайтах. Любая ошибка в нём — это ошибка на чужой странице. Поэтому правила жёсткие.

**Код**
- Без зависимостей и без фреймворков. `loader.js` — не больше 10 КБ gzip. Виджет целиком — не больше 30 КБ gzip.
- Не выполняем код, пришедший с сервера. Никакого `eval`, `new Function`, `innerHTML` из ответа API. Текст из API — только через `textContent`.
- В глобальной области — не больше одного имени (например `window.OKO`), и только если без него не обойтись.
- Стили изолируем: Shadow DOM или iframe. Стили виджета не утекают на страницу хоста, стили хоста не ломают виджет.
- Из DOM хоста трогаем только свой контейнер, который добавляем в конец `body`.

**Поведение при сбоях**
- Любой запрос с таймаутом 2 секунды. При ошибке, таймауте или `403` виджет молча скрывается.
- Никаких `alert`, `console.error` и всплывающих сообщений на странице хоста.
- `loader.js` ничего не запрашивает до события `load` страницы и не блокирует её рендер.

**Идентификатор оценившего**
- `crypto.randomUUID()`, один раз на браузер.
- Реализовано: `localStorage` сайта хоста через `loader.js`, в iframe передаётся через `postMessage` (сторонние cookie в iframe режут Safari и Chrome). Ключ хранилища `oko:<начало ключа>`. Нужно подтвердить с Данилом.
- В хранилище — только идентификатор и дата последнего показа. Больше ничего о пользователе.

**Публичный ключ**
- Передаётся в `data-`-атрибуте скрипта. Он не секрет, но и не нужно разглашать его без причины.
- Секретный ключ виджету не нужен и в его код не попадает. Если он там оказался, это инцидент.

**Версии**
- Путь `/widget/v1/`. Ломающие изменения — только в `/widget/v2/`. Старые сайты продолжают работать на v1.

**Доступность**
- Кнопки с `aria-label`. Фокус остаётся внутри открытой карточки. Esc закрывает её.

**Тесты виджета**
- Наш сервер выключен (домен заблокирован): страница хоста грузится, виджета нет, ошибок в консоли нет.
- Сервер отвечает `500`: то же самое.
- Сервер отвечает 10 секунд: страница хоста не задержана, виджет скрыт по таймауту.
- Страница-заглушка на трёх стеках: обычный HTML, PHP-шаблон, React. Конфликтов с библиотеками хоста нет.

## Команды

- `npm run demo` — всё сразу: мок-сервер (:4010), панель (:5173), тестовые сайты (:5500 HTML, :5501 PHP, :5502 React);
- `npm run mock` + `npm run dev` — панель на stateful-моке;
- `npm run dev:backend` — панель против backend на `localhost:8080` (backend с `OKO_PUBLIC_ORIGIN=http://localhost:5173`, профиль `dev`);
- `npm run mock:prism` + `npm run dev:prism` — строго по контракту (Prism, без состояния);
- `npm run gen:api` — перегенерировать `src/api/schema.d.ts` после изменения контракта;
- `npm run typecheck`, `npm test` — типы, юнит-тесты, сборка виджета и проверка веса;
- `npm run test:widget` — сквозные проверки виджета в Chromium (первый раз: `npx playwright install chromium`);
- `npm run build`, `npm run build:widget` — сборка панели в `dist/` и виджета в `widget/dist/`;
- `npm run build:deploy` — статика для nginx: `dist-deploy/panel` и `dist-deploy/widget/v1`;
- `OKO_TEST_KEY=pk_… npm run test-pages` — тестовые сайты с ключом продукта из настоящего backend.

## Где что

- `src/api/hooks.ts` — по одному хуку на операцию контракта, имя = `operationId`.
- `src/api/schema.d.ts` — генерируется, руками не правим.
- `src/lib/format.ts` — правила показа: средняя, индекс, цвета, n < 20, день по Томску.
- `src/lib/health.ts` — лампочка продукта из статусов сервисов.
- `widget/src/` — `loader.js` (на чужом сайте), `frame.js` + `frame.css` (внутри iframe; саму страницу iframe генерирует backend).
- `mock/` — мок-сервер; повторяет контракт, но это не backend.

## Частые ошибки

- Код вставки — не `<script async src>`, а сниппет, который добавляет скрипт после `load` (`src/lib/embed.ts`): иначе медленный сервер ОКО задерживает событие `load` у сайта.
- Prism отдаёт пути без `/api/v1` — для него только `npm run dev:prism`.
- Backend v1 отвечает 404 на ещё не реализованные эндпоинты (dashboard, stats, ratings, releases). Не показываем это как «нет доступа»: `isNotImplemented` + `NotImplementedState` из `components/States.tsx`.
- Без `OKO_PUBLIC_ORIGIN=http://localhost:5173` у backend вход в панель уводит на :8080, а оценки из iframe получают 403 `ORIGIN_NOT_ALLOWED`.
- `useState(() => takeSomething())` в StrictMode вызывается дважды: одноразовые значения сначала «подсматриваем», чистим в `useEffect`.
- Сообщения браузера «Framing … violates Content-Security-Policy» и «Failed to load resource» на чужом сайте — это браузер, а не наш код; убрать их нельзя.
