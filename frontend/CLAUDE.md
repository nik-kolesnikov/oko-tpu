# Frontend и виджет ОКО

Зона: Таир. Контракт: `../contracts/oko-openapi.yaml`. Макеты: Figma, владелец — Максим.

Экраны здесь не описываем. Реализуем по макету. Если макет и спецификация расходятся, спрашиваем Максима или Николая, а не придумываем.

## Структура

```
frontend/
├── src/           панель (React SPA): вход, дерево продуктов, карточка продукта, форма продукта, админ
├── widget/        виджет для чужих сайтов: loader.js и frame.js; не React
└── mock/          мок-сервер по спецификации (Prism) — фронт работает на нём до готовности backend
```

## Панель

- Работаем только на данных API. Не обращаемся к полям, которых нет в спецификации.
- У каждого экрана три состояния: загрузка, пусто, ошибка.
- Тексты оценок, названия и комментарии выводятся как текст, не как HTML. `dangerouslySetInnerHTML` и `innerHTML` не используем.
- Изменяющие запросы отправляем с `X-XSRF-TOKEN` из cookie `XSRF-TOKEN`.
- Публичный ключ виджета всегда виден во вкладке «Интеграция». Его можно копировать.
- Секретный ключ показываем один раз сразу после выпуска. Затем очищаем состояние и не сохраняем нигде.
- Ключи и токены не кладём в `localStorage` и `sessionStorage`.
- Лампочки — по статусам из API. Цвет и подпись: `up` — зелёный, `down` — красный, `unknown` — серый «нет данных».
- Жёлтая лампочка («часть сервисов не работает») в спецификации пока не отражена. Наш вариант — жёлтый, нужен PR в спецификацию. До его принятия не придумывай жёлтый на клиенте.

## Виджет — зона повышенного риска

Виджет работает на чужих сайтах. Любая ошибка в нём — это ошибка на чужой странице. Поэтому правила жёсткие.

**Код**
- Без зависимостей и без фреймворков. `loader.js` — не больше 10 КБ gzip. Виджет целиком — не больше 30 КБ gzip.
- Не выполняем код, пришедший с сервера. Никакого `eval`, `new Function`, `innerHTML` из ответа API. Текст из API — только через `textContent`.
- В глобальной области — не больше одного имени (например `window.OKO`), и только если без него не обойтись.
- Стили изолируем: Shadow DOM или iframe. Стили виджета не утекают на страницу хоста, стили хоста не ломают виджет.
- Из DOM хоста трогаем только свой контейнер, который добавляем в конец `body`.

**Поведение при сбоях**
- Любой запрос с таймаутом 2 секунды. При ошибке, таймауте или `403` виджет молча скрывается.
- Никаких `alert`, `console.error` и всплывающих сообщений на странице хоста.
- `loader.js` ничего не запрашивает до события `load` страницы и не блокирует её рендер.

**Идентификатор оценившего**
- `crypto.randomUUID()`, один раз на браузер.
- Открыто: где хранить. Cookie внутри iframe на нашем домене — это cookie третьей стороны, их режут Safari и Chrome. Варианты: `localStorage` сайта хоста через `loader.js` с передачей в iframe. Выбираем после проверки в браузерах с заблокированными сторонними cookie. Согласовать с Данилом.
- В хранилище — только идентификатор и дата последнего показа. Больше ничего о пользователе.

**Публичный ключ**
- Передаётся в `data-`-атрибуте скрипта. Он не секрет, но и не нужно разглашать его без причины.
- Секретный ключ виджету не нужен и в его код не попадает. Если он там оказался, это инцидент.

**Версии**
- Путь `/widget/v1/`. Ломающие изменения — только в `/widget/v2/`. Старые сайты продолжают работать на v1.

**Доступность**
- Кнопки с `aria-label`. Фокус остаётся внутри открытой карточки. Esc закрывает её.

**Тесты виджета**
- Наш сервер выключен (домен заблокирован): страница хоста грузится, виджета нет, ошибок в консоли нет.
- Сервер отвечает `500`: то же самое.
- Сервер отвечает 10 секунд: страница хоста не задержана, виджет скрыт по таймауту.
- Страница-заглушка на трёх стеках: обычный HTML, PHP-шаблон, React. Конфликтов с библиотеками хоста нет.

## Команды

Появятся после каркаса (этап 0). Ориентир:
- `cd frontend && npm run dev` — панель на моке;
- `npm run dev:backend` — панель против `localhost:8000`;
- `npm run build:widget` — сборка виджета;
- `npm test` — тесты, в том числе размер виджета.
